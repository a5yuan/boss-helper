# 统计页主数字用「草稿填写数」，不叫「投递数」

ADR-0003 决定「总投递数只算 `submitted`」。上线一天后发现主数字对使用者几乎没有信息量：BOSS 走 `prefill_chat`，所有动作都是草稿（25 条），真实送达只有智联的 1 条。顶部显示「1」，而使用者当天实际填了 25 份草稿——数字没涨，人却在干活，看着像统计坏了。

所以主数字改成草稿数。但**标题必须叫「草稿填写数」，不能叫「投递数」**：25 个草稿一家公司都没收到，叫投递数就是在说谎，也违反 `GLOSSARY.md` 里 `drafted` 的定义。送达数退到副标题，仍然可见。

## Considered Options

- **保持 ADR-0003 不变（只算 `submitted`）**：诚实，但主数字长期是 0 或 1，页面失去意义。使用者真正能掌控、能优化的量是「填了多少份草稿」。
- **合并成一个「投递数」= submitted + drafted**：最省事，但违反 `GLOSSARY.md` 的明确禁令——两种状态混在一起，数字涨了却没有一家公司收到简历，比不显示更糟。
- **双主数字并排（一格放两个大数）**：信息完整，但一格内比较两个量反而看不清，且 1280 宽窗口下会挤。
- **六格（草稿 / 送达 / 完成率 / 今日草稿 / 耗时 / Token）**：一格一件事最清楚，但六格挤成一行，字号要缩。

选了「主数字 = 草稿，副标题 = 送达」。一格只讲一件事，主数字给使用者能动的量，副标题老实交代送达了几条。

## 连带调整

- **「成功率」改名「动作完成率」**。原口径是 `(submitted + drafted) / attempts`，而 `attempts` 本身就等于 `submitted + drafted + 非闸门失败`，所以只要不报错就恒为 100%——它测的是「有没有报错」，不是「投得成不成」。改成有信息量的口径需要新数据源（BOSS 草稿发没发出去现在拿不到），所以先改名，不假装它测的是成功率。
- **「AI 花费」改成「AI Token」**。没配 `ai.pricing` 单价表时，这一格只显示 token 数；框里写「花费」而显示 token 是名不副实。折线图纵轴同步从「调用次数」换成每桶 token 合计，否则 KPI 和趋势图讲的不是一件事。

## Consequences

- 主数字从「结果量」变成「过程量」。使用者看到的是自己的动作量，不是市场反馈量——需要在副标题里持续交代送达数，不能让它消失。
- `/api/stats` 的每个维度桶要补 `tokens_in` / `tokens_out`，折线图才有东西可画。
- ADR-0003 里「`drafted` 只在图表里单独显示」的部分被取代；「不能与 `submitted` 合并成一个投递数而不加区分」这一条**仍然有效**，本 ADR 是遵守它而不是推翻它。
- 如果将来 BOSS 能确认草稿是否被发出，「动作完成率」可以换成真实口径，届时需要新的 ADR。
